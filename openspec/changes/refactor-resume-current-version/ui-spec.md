## 页面目标

保持现有简历编辑页布局和保存状态位置不变，仅修正快照恢复、删除和自动保存的交互语义。命名快照是可继续编辑的分支；当前分支必须先切换后才能删除，避免页面内容与分支标记失去对应关系。

## 结构与视觉

- 不新增页面、卡片、弹窗层级或字体选项。
- 快照列表继续使用现有组件、颜色、字号、间距、圆角和响应式规则。
- 底部版本线仅在存在至少两个命名分支时显示；零个或一个分支时隐藏。
- 保存状态继续位于简历预览区域中间的既有稳定槽位，不移动标题、缩放和打印控件。
- 本次不新增装饰性元素、动画或成功 Toast。

## 交互状态

| 操作 | 加载状态 | 成功状态 | 失败状态 |
|---|---|---|---|
| 选择快照 | 禁用重复选择，保留当前页面 | 服务端 current 内容载入编辑区，保存状态与返回版本对齐 | 保留原本地内容，显示现有错误通知 |
| 创建快照 | 等待 pending revision 云端确认 | 列表新增稳定 manual，当前内容不变 | 不新增本地伪快照 |
| 删除当前基准快照 | 不打开删除确认、不发送删除请求 | 提示“请先切换到其他分支再删除” | 保留原分支和正文 |
| 删除非当前快照 | 保留现有删除确认 | 无投递关联时从列表移除 | 有投递关联时保留列表项并提示无法删除 |
| 自动保存 | 使用现有“正在保存”状态 | 仅 PostgreSQL commit 后显示“已自动保存” | 显示待同步/失败，不覆盖本地内容 |

- 云端保存失败只在保存状态槽位显示一次，并在该位置提供“重试”；不得同时生成重复的 workspace notice。

## 响应式与无障碍

- 沿用现有桌面、窄屏布局，不增加固定宽度内容。
- 现有保存状态继续使用 `aria-live="polite"`；错误使用已有可访问通知机制。
- 快照操作按钮在请求期间必须有 `disabled` 状态，键盘焦点不得丢失到不可见元素。

## 验证

- 桌面与窄屏下快照操作不改变工具栏尺寸，不遮挡预览与缩放控件。
- 模拟恢复失败、保存冲突、删除被引用快照，确认本地正文仍保留且不会出现本地/云端覆盖选择弹窗。
- 当前在 A 时点击删除 A，确认只提示先切换且不发 DELETE；切到 B 后删除 A，确认先检查投递关联，无关联时删除、有引用时拒绝。删除后只剩一个分支时版本线隐藏。
