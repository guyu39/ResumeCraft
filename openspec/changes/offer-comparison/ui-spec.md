# Offer 对比分析 UI 规范 — `/applications?view=offers`

> 设计依据：`ui-ux-pro-max` Radar/Spider（多维对比）+ Compare Categories（Bar）+ Before-After Transformation 对比模式。沿用现有令牌，Offer 语义色统一 `emerald #10B981`（正向），警示用 `red #DC2626`。

## 一、页面目标

用户手上有 2–5 个 offer 时，能在一屏内横向比较薪资与软性维度，并通过自定义权重得到一个可解释的推荐排序，而不是靠感觉。

## 二、结构分层

```
┌────────────────────────────────────────────────────────────────┐
│ 视图切换 Tab：[列表] [日程] [数据分析] [Offer 对比 ←active]        │
├────────────────────────────────────────────────────────────────┤
│ ① Offer 卡片行（横向滚动，每卡 280px）                            │
│   [字节 P2-1  ⏰3天]  [阿里 P6]  [腾讯 T9]  ...                  │
│   卡内：公司/职位 · 总包 · 城市 · 综合分（大号）· 编辑按钮           │
├────────────────────────────────────────────────────────────────┤
│ ② 权重调节区（可折叠，默认展开）                                   │
│   薪资 [====●----] 40%   成长 [==●------] 25%                    │
│   团队 [=●-------] 15%   强度 [=●-------] 10%  通勤 [●----] 10%  │
│   [重置默认权重]   权重总和自动归一化为 100%                        │
├────────────────────────────────────────────────────────────────┤
│ ③ 综合评分对比（水平条形图，按分数降序）                            │
│   字节  ████████████ 87.5                                       │
│   阿里  █████████    76.2                                       │
├────────────────────────────────────────────────────────────────┤
│ ④ 维度雷达图（≤3 个 offer 时显示，>3 个自动隐藏改用⑤表格）           │
├────────────────────────────────────────────────────────────────┤
│ ⑤ 明细对比表（行=维度，列=offer，最优值高亮）                       │
└────────────────────────────────────────────────────────────────┘
```

## 三、组件规范

### ① Offer 卡片

- 尺寸 `w-[280px] shrink-0`，容器 `overflow-x-auto` 横向滚动 + `snap-x`。
- 卡片 `card-flat p-4 border-l-4 border-emerald-500`；推荐首位（综合分最高）额外加 `ring-2 ring-emerald-400` + 右上角 `「推荐」` 徽标。
- 内容层级：
  - 公司名 `text-sm font-semibold text-ink truncate`
  - 职位 `text-xs text-muted truncate`
  - 总包 `text-2xl font-bold tabular-nums text-ink`（单位「万/年」）
  - 城市 + 到岗日 `text-xs text-muted`
  - 综合分 `text-lg font-bold text-emerald-600 tabular-nums`
- **有效期倒计时角标**：`deadline - now ≤ 3 天` 时右上角显示 `bg-red-500 text-white text-[10px] rounded px-1.5` 「⏰N天」；已过期显示灰色「已过期」。
- 未录入明细的 offer：卡片置灰 + 「补充明细」CTA 按钮。

### ② 权重调节

- 5 个维度滑块（原生 `<input type="range" min=0 max=100>`），沿用项目已有表单样式。
- 每个滑块右侧显示归一化后的百分比（实时更新，`tabular-nums`）。
- 默认权重：薪资 40 / 成长 25 / 团队 15 / 强度 10 / 通勤 10。
- 权重变化即时重算 ③④⑤（纯前端计算，无请求）。
- 权重存 `localStorage`（key `offerWeights`），下次进入保留；「重置默认权重」按钮清除。

### ③ 综合评分对比

- Recharts `BarChart layout="vertical"`，降序排列（符合 charts.csv "Always sort descending by value"）。
- Bar 色 `#10B981`；首位（最高分）用 `#059669` 深色区分。
- 每条 bar 尾部显示数值标签（charts.csv: "Value labels on each bar by default"）。
- **评分算法**（前端，可解释）：
  1. 每个维度在所有 offer 内做 min-max 归一化到 0–100（薪资取总包；4 项自评直接 `star/5*100`）。
  2. 加权求和 `Σ(归一化值 × 归一化权重)`。
  3. 缺失维度按该维度所有 offer 的均值填补，并在表格中标注「估算」。

### ④ 维度雷达图

- Recharts `RadarChart`，5 轴（薪资/成长/团队/强度/通勤），使用归一化后的 0–100 值。
- ≤3 个 offer 才渲染（charts.csv: "2–3 datasets maximum per chart"）；超过 3 个自动隐藏并提示"offer 较多，请查看下方明细表"。
- 各 offer 用不同色相 + 30% 填充；边框满不透明。
- **必须**同时提供 ⑤ 明细表作为强制替代视图（charts.csv 要求 "Grouped bar chart as mandatory alternative"）。

### ⑤ 明细对比表

- 表头固定（`sticky top-0`），首列维度名固定（`sticky left-0`）。
- 行分组：**薪资**（Base / 浮动 / 股票 / 签字费 / 总包）、**硬性条件**（城市 / 到岗日 / 有效期）、**软性自评**（成长 / 团队 / 强度 / 通勤）。
- **最优值高亮**：每行最优单元格 `bg-emerald-50 text-emerald-700 font-semibold`；薪资类越大越优，工作强度越小越优（口径需在表头注明「强度：分越高=越轻松」）。
- 星级自评用 `★★★☆☆` 文本 + 数字，不只靠图形（无障碍）。
- 未录入 `text-slate-400 「未录入」`；估算值加 `title` tooltip 说明。
- 移动端 `overflow-x-auto` 横向滚动（UX 指南 Table Handling）。

## 四、交互与状态

- **空态**（无 offer）：居中 `Trophy` 图标 + "还没有 offer 记录，把投递状态改为 offer 后即可在此对比" + 「去投递列表」按钮。
- **仅 1 个 offer**：隐藏 ③④，只显示 ① 卡片 + ⑤ 明细表，提示"再拿一个 offer 就能开启对比"。
- **编辑 offer**：点击卡片「编辑」→ 打开现有投递详情抽屉并自动滚动/展开到 offer 明细表单区。
- **表单校验**：薪资字段 `inputmode="decimal"` 只接受非负数；`deadline` 不早于今天；校验 onBlur（UX 指南 Inline Validation）。
- **保存反馈**：按钮 loading 态禁用防重复提交，成功 toast「offer 明细已保存」并刷新对比。
- **URL 状态**：`?view=offers`，deep-link 可分享（权重不入 URL，属个人偏好）。

## 五、响应式

| 断点 | 布局 |
|---|---|
| `>=1280px` | ① 横向卡片全展示；②5 滑块一行；③④ 左右并排；⑤ 全宽 |
| `768~1280px` | ② 滑块 2 行；③④ 纵向堆叠 |
| `<768px` | ① 单卡宽度 `85vw` snap 滑动；② 滑块单列；④ 雷达图隐藏；⑤ 横向滚动 |

## 六、无障碍

- 权重滑块 `<label for>` 关联 + `aria-valuetext="薪资权重 40%"`。
- 雷达图 `role="img"` + `aria-label` 概述，并明确指向下方表格作为无障碍替代。
- 最优值单元格除底色外附加 `✓` 图标或 `aria-label="最优"`，不单靠颜色传达（WCAG 1.4.1）。
- 倒计时角标 `role="status"`，临期用文字「剩 3 天」而非仅红色。
- 综合分变化时 `aria-live="polite"` 播报新的推荐首位。
- 所有交互元素 `focus:ring-2 focus:ring-primary`，Tab 顺序与视觉顺序一致。

## 七、避免的反模式

- 不用 `#F59E0B` 以外的第三种警示色，避免语义混乱。
- 不做"自动帮你选哪个 offer"的强判断结论，只给可解释的加权排序（决策权归用户）。
- 不在前端硬编码汇率做多币种换算；不同币种在表格中分行显示并标注币种，不强行合并。
