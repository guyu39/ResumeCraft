# 邮件集成 UI 规范 — `/applications?view=inbox` + 邮箱设置弹窗

> 设计依据：`ui-ux-pro-max` UX Guidelines (Empty States, Loading, Inline Validation, Submit Feedback)。沿用现有令牌与 `card-flat` 基类。邮件收件箱采用列表 + 侧面板详情的经典二栏模式（类 Gmail），适合扫描式浏览与逐条确认。

## 一、页面目标

用户配好邮箱后，可在此视图看到系统自动识别出来的面试/笔试邮件草稿，逐条确认是否写入投递面试记录。核心诉求是"快速过滤 + 一键确认"。

## 二、入口

- `/applications` 视图切换 Tab 新增「收件箱」（`view=inbox`）。仅在用户已配置且启用邮箱时展示该 Tab。
- 首页工作台待办区块可新增"N 条待确认面试邀请"行，点击跳 `/applications?view=inbox`（此为可选增强）。
- 导航菜单/设置中显示「邮箱绑定」入口。

## 四、邮箱配置弹窗 (`EmailAccountDialog`)

- 入口：设置面板 / 收件箱视图空态 CTA。
- 表单字段：IMAP 服务器 / 端口 / 邮箱地址 / 授权码（password input）/ 启用开关。
- 常见服务器预设按钮（Gmail / QQ / 163 / Outlook 点击自动填充 host+port）。
- 「测试连接」按钮：调用 `POST /api/email/test-connection`，成功绿色勾，失败红色错误信息（具体 IMAP 报错翻译为中文提示）。
- 「保存」按钮：loading 态禁用 → 成功 toast「邮箱绑定成功」→ 关闭弹窗。
- 「解绑」按钮：需二次确认 ConfirmDialog（"解绑将停止自动同步且删除所有草稿"），确认后清除凭证 + 删除草稿。
- 安全提示文案：「授权码经 AES-256 加密存储，我们不保存明文密码」，显示在表单下方 `text-xs text-muted`。

## 五、草稿列表

- 每行：状态标签（`pending` 蓝底 / `confirmed` 绿底 / `ignored` 灰底）+ 发件人域名 + 主题截取前 30 字 + 识别时间（相对时间格式：UX 指南 Date Formatting）。
- 默认筛选「仅待处理」；可切换「全部」。
- 选中行 `bg-primary/5 border-l-2 border-primary`。
- 列表加载用骨架 `animate-pulse`（5 行灰条）。
- 空态（无待处理）：`Mail` 图标 + "所有邮件已处理，等待新的面试邀请" / 未配置时："绑定邮箱后系统将自动识别面试邀请"+ 「绑定邮箱」按钮。

## 六、草稿详情面板

- 展示原始邮件元数据（发件人 / 主题 / 正文片段前 200 字 `text-xs text-muted bg-canvas rounded p-3`）。
- AI 抽取结果结构化展示（`card-flat` 内的字段列表，字段对齐）：
  - 如果 AI 对某字段不确定，标注 `「低置信」text-amber-500`，用户可手动修正。
  - 时间字段点击可编辑（`<input type="datetime-local">`）。
- 匹配投递下拉：自动按公司名模糊匹配已有投递（最多展示 3 条），用户可选择或新建。
- 操作按钮区域：
  - 「✓ 确认写入」（主按钮 `bg-primary`）：写入面试记录到匹配的投递。
  - 「✗ 忽略」（次要按钮 `text-muted`）：标记 ignored，从待处理列表移除。
  - 确认后行状态实时更新，详情面板自动跳到下一条待处理。

## 七、「立即同步」按钮

- 点击后：loading 旋转图标 + 禁用 2 秒防抖 + 完成后 toast「同步完成，新增 N 条草稿」。
- 同步失败：toast 错误信息「IMAP 连接失败，请检查邮箱设置」。
- 「上次同步 xx 分钟前」用相对时间自动更新（每 30 秒刷新显示）。

## 八、响应式

| 断点 | 布局 |
|---|---|
| `>=1024px` | 左右二栏（列表 40% / 详情 60%） |
| `<1024px` | 单列：列表全宽；点击行后 push 进详情视图（返回箭头回到列表），移动端经典导航模式 |

## 九、无障碍

- 列表行 `role="listbox"` / `role="option"` + `aria-selected`；键盘 ↑↓ 切换行，Enter 打开详情。
- 「确认写入」按钮 `aria-label="确认将此面试邀请写入投递记录"`。
- 草稿状态标签 `role="status"` 带文字，不单靠颜色。
- `prefers-reduced-motion`：禁用列表行 hover 的位移动画。
- 授权码输入框 `autocomplete="off"` 防自动填充泄漏。

## 十、安全交互约束

- **绝不自动写入面试记录**：所有从邮件识别的信息必须经用户「确认」按钮才落库，详情面板明确标注"此草稿尚未写入，确认后才会出现在日程中"。
- 授权码不回显（表单 placeholder "已绑定" / 类型 password，「修改」需重新输入）。
- 「解绑邮箱」需 ConfirmDialog 二次确认。
