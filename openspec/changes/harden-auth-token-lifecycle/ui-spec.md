## 页面目标与场景

- 会话明确过期后，让用户知道需要重新登录，并在登录成功后返回原工作位置。
- 被其他设备顶号时继续使用现有的明确告警文案。
- 网络错误、网关错误和刷新重试过程保持无感，不制造误导性的退出提示。

## 结构与组件

- 不新增页面、弹窗、导航项或常驻状态组件。
- 复用 `LoginPage` 登录卡片标题下方、登录方式 Tab 上方的现有告警区域。
- 告警内容由 URL 中一次性的 `reason` 决定：
  - `kicked`：`您的账号已在其他设备登录，当前会话已失效，请重新登录。`
  - `expired`：`登录状态已失效，请重新登录。登录后将返回之前的页面。`
- 页面读取后移除 `reason`，但保留 `return` 参数，避免刷新重复制造提示并确保登录后返回。

## 视觉规范

- 完全沿用现有登录卡片样式和设计 Token，不采用 UI Pro Max 自动推荐的独立落地页、玻璃风格重构或新配色。
- 告警容器：`mt-4 flex items-start gap-2 rounded-lg border border-amber-200 bg-amber-50 px-3 py-2.5`。
- 文本：`text-sm text-amber-800`，行高沿用浏览器/项目默认设置，字距为 `0`。
- 图标：Lucide `AlertTriangle`，`h-4 w-4 flex-shrink-0`，与首行文本顶部对齐。
- 不新增阴影、动画或装饰元素。

## 交互状态

- 常态：未携带终态原因时不显示告警区域，布局保持现状。
- 会话过期：告警静态展示，不自动消失；用户可直接使用密码或验证码登录。
- 被顶号：保留现有静态告警行为。
- 刷新中：不显示可见状态，不阻塞当前页面操作。
- 临时失败：不跳登录页、不显示会话告警；原业务请求按其现有错误反馈处理。
- 登录成功：使用经过校验的站内 `return` 路径跳回原页面；缺失或非法时回到 `/`。

## 响应式

- 桌面、平板、移动端均位于登录卡片内容流内，宽度随卡片自适应。
- 375px 下图标固定 16px、文本允许自然换行，不截断，不产生横向滚动。
- 不改变现有 768px、1024px、1440px 布局和登录卡片定位。

## 无障碍与易用性

- 告警容器使用 `role="alert"`，但不主动抢占焦点。
- 图标使用 `aria-hidden="true"`，完整含义由文本表达，不只依赖颜色。
- 琥珀色前景/背景保持足够对比度；键盘焦点和表单交互沿用现有实现。
- `return` 仅允许站内绝对路径，拒绝协议相对地址和外部 URL。

## 验收清单

- `reason=expired` 与 `reason=kicked` 显示不同文案。
- 读取 `reason` 后 URL 清理该参数并保留 `return`。
- 临时网络错误不会进入登录页。
- 重新登录后返回原站内页面，非法返回地址回退 `/`。
- 在 375px 与桌面视口中告警不与表单、Tab 或卡片边界重叠。
