# 统计分析扩展 UI 规范 — `/applications?view=analytics`

> 设计依据：`ui-ux-pro-max --design-system` 输出（Style: Data-Dense Dashboard；Density 8/10）。沿用现有 `FunnelAnalytics.tsx` 的令牌体系（primary #1A56DB / indigo #6366F1 / amber #F59E0B / emerald #10B981 与 `card-flat` 基类），不新增设计系统，保持全站漏斗色彩语义一致。

## 一、页面目标

用户在分析视图打开的第一屏应看到"当前投递漏斗（现状）"，第二屏能下拉看到"最近趋势（进步/退步）"与"面试效率（多少轮换 1 个 offer）"，第三屏是"简历版本对比（原有）"。

## 二、结构分层

```
┌─────────────────────────────────────────────────────────────┐
│ ① KPI 概览（6 卡，保留不变）                                  │
├─────────────────────────────────────────────────────────────┤
│ ② 投递进展（阶段分布环图 + 转化漏斗，保留不变）                 │
├─────────────────────────────────────────────────────────────┤
│ ③【新增】漏斗趋势                                             │
│   顶部：分桶切换 [周 / 月]  时间范围 [近 3 个月 ▼]              │
│   左侧：投递/面试/Offer 三线时序（Line Chart，堆叠可选）        │
│   右侧：整体回复率 & Offer 率趋势（次要 Y 轴，虚线）             │
├────────────────────────────┬────────────────────────────────┤
│ ④【新增】面试轮次分布        │ ⑤【新增】阶段停留时长（中位数天数）│
│   均值 / 中位数 / 最长 KPI  │   投递→笔试 / 笔试→面试 /        │
│   下方：轮次直方图（Bar）    │   面试→Offer 三条水平进度条       │
├────────────────────────────┴────────────────────────────────┤
│ ⑥ 简历版本对比（保留不变）                                    │
└─────────────────────────────────────────────────────────────┘
```

## 三、组件规范

### ③ 漏斗趋势卡片

- **图表类型**：`Recharts` LineChart（沿用现有 recharts 依赖）；主 Y 轴数值，副 Y 轴百分比。
- **序列**：
  - 投递数（实线 #1A56DB，圆点 dot=false）
  - 面试数（实线 #F59E0B）
  - Offer 数（实线 #10B981，末点 dot=true 强化终点）
  - 回复率（虚线 #6366F1，dash=[4,4]，副轴 %）
  - Offer 率（虚线 #10B981 深色，副轴 %）
- **色盲无障碍**：线型必须区分（实/虚），不能仅靠颜色；同时提供 Legend 可点击隐藏系列。
- **交互**：hover 显示当桶详情（日期区间、5 个指标值）；`prefers-reduced-motion` 关闭进场动画。
- **分桶控制**：`weekly` 默认；用户切 `monthly` 时保留时间范围；时间范围默认"近 3 个月"，可选"近 6 个月 / 近 1 年 / 全部"。
- **空态**：投递数 < 4 的时间桶时显示"数据积累中，继续投递将解锁趋势"，隐藏图表但保留控制条。

### ④ 面试轮次分布

- **KPI 三卡**：均值（`text-xl font-bold text-ink`）/ 中位数 / 最长；单位"轮"。
- **直方图**：X 轴 = 面试轮次（1 / 2 / 3 / 4+），Y 轴 = 该轮次的投递数；bar 颜色 #F59E0B，`isAnimationActive={!reduced}`。
- **数据口径**：仅统计 `status ∈ (interview / offer / rejected 且经历过面试)` 的投递；单条投递按其 `job_application_interviews` 记录数计算。

### ⑤ 阶段停留时长

- **展示**：3 条水平进度条 + 数字标签"中位数 N 天 / 最长 N 天"。
- **颜色**：
  - 投递→笔试：#6366F1
  - 笔试→面试：#F59E0B
  - 面试→Offer：#10B981
- **数据口径**：从 `job_application_status_events` 相邻两条计算时间差；取每对状态转换的中位数（P50）与最大值（P100），忽略同一投递多次回退的异常样本。

## 四、交互与状态

- 面板加载：三个新卡片各自独立请求，任一失败仅该卡片显示"加载失败 · 重试"，不阻塞其他内容。
- 首次接入用户（无任何投递记录）：直接沿用现有 `isEmpty` 空态，隐藏所有新卡片。
- 时间范围切换：URL 参数 `?view=analytics&range=3m|6m|1y|all&bucket=week|month`，实现 deep-linking，与 UX 指南 "Deep Linking / High" 一致。
- 键盘可达：分桶切换按钮 `role="tab"` + `aria-selected`；时间范围下拉沿用现有 `StyledSelect`。

## 五、响应式

| 断点 | 布局 |
|---|---|
| `>=1280px` | ③ 独占宽；④⑤ 左右并排 `grid-cols-2` |
| `>=768px` | ③④⑤ 全部纵向堆叠占满宽度 |
| `<768px` | 同上；图表 `ResponsiveContainer` 自适应，最小高度 220px |

## 六、无障碍

- 所有新增图表：外层 `role="img"` + `aria-label` 概括描述（例："投递趋势时序图，近 3 个月按周分桶"）。
- 颜色对比：所有系列色对白底 ≥ 3:1（WCAG AA large text），虚线 + 实线区分确保色盲可读。
- 数字全部使用 `tabular-nums` 保证滚动/切换时不跳位。
- 骨架：加载时使用 3 层 `animate-pulse` 灰条替代图表区，避免 CLS。
