# 首页工作台 UI 规范（`/`）— 迭代 v4

> 设计依据：内容分层原则（状态与行动优先，资讯与素材靠后）。沿用现有令牌（primary/canvas/surface/line/ink/muted/brand-soft）与 `card-flat` 卡片基类，不新增设计系统。
> 本文件为 v3 的迭代补充，覆盖本轮调整：新增求职概览 KPI 条；待办、今日新增岗位从右下角悬浮球提升为页面正文常驻区块；AI 日报/GitHub 项目、简历项目推荐整体下移一层；GitHub 项目卡片新增 AI 中文加工展示（一句话简介 + 求职视角亮点点评）。

## 一、页面目标与使用场景

- **定位**：求职工作台首页。核心诉求调整为"进来先看自己的求职状态"，而非"进来先看行业资讯"。
- **核心场景**：用户打开首页第一眼看到求职漏斗概览（KPI）与近期待办/新增岗位；资讯与项目素材作为辅助内容下移，仍可浏览但不再占据首屏视觉焦点。
- **设计原则**：状态与行动优先（Action First）；正文常驻优于悬浮交互（减少一次点击才能看到关键信息）；资讯/素材保留但降权。

## 二、页面结构分层与组件排布

```
┌────────────────────────────────────────────────────────────────┐
│ ① HomeHeader 顶部导航（不变，fixed，h-14）                       │
├────────────────────────────────────────────────────────────────┤
│ ② 问候区（保留，精简为单行标题 + 日期）                            │
├────────────────────────────────────────────────────────────────┤
│ ③ 求职概览 KPI 条（新增）                                         │
│   [已投递 N] [笔试 N] [面试 N] [Offer N]  4 卡横排，整条可点击      │
│   跳转 /applications?view=analytics                              │
├───────────────────────────────┬────────────────────────────────┤
│ ④ 近期笔面试待办（新增，正文化）  │ ⑤ 今日/昨日新增岗位（新增，正文化） │
│   最多 5 条，「查看全部」跳        │   最多 5 条，「查看全部」跳        │
│   /applications                 │   /jobs                          │
├───────────────────────────────┴────────────────────────────────┤
│ ⑥ AI 日报 / GitHub 项目（Tab 切换，保留交互，整体下移一层）         │
│   GitHub 卡片新增：AI 中文简介 + 求职视角亮点点评（有则展示，       │
│   无则回退英文 description）                                      │
├────────────────────────────────────────────────────────────────┤
│ ⑦ 简历项目推荐（保留，位置不变，整体下移一层）                       │
└────────────────────────────────────────────────────────────────┘
```

**移除**：右下角悬浮球组件（`FloatingActions.tsx` 的悬浮球 + 展开面板交互整体废弃），其承载的待办/新增岗位内容迁移至 ④⑤ 正文区块常驻展示。

**桌面（`>=1024px`）**：④⑤ 左右并排（`grid-cols-2`）；⑥⑦ 各自占满宽度纵向堆叠。
**移动/平板（`<1024px`）**：④⑤ 单列堆叠（待办 → 新增岗位）；⑥⑦ 不变。

## 三、统一视觉规范

沿用 v1-v3 全部令牌体系与 `card-flat` 基类。新增：

- **KPI 卡**：4 卡横排于一个 `card-flat` 容器内，卡间用 `divide-x divide-line` 分隔（不单独加卡片阴影/圆角，保持轻量）；数值 `text-2xl font-bold text-ink tabular-nums`，标签 `text-xs text-muted`；配色复用 `FunnelAnalytics.tsx` 已有的 `TONE` 语义（blue=已投递/indigo=笔试/amber=面试/emerald=offer）图标底色，保持全站漏斗色彩语义一致。整条 KPI 容器可点击（`role="button"`），hover 时 `border-primary/40`。
- **待办/新增岗位正文区块**：复用原悬浮面板内的行样式（时间+类型标签+公司名+跳转箭头 / 公司+职位+地点+开放日期标签），去掉悬浮相关的 `fixed`/`z-50` 定位与展开动画，改为普通 `card-flat` 区块，标题行同构对齐 `DailyReport`/`Projects` 的 `h-14` 头部样式（图标 + 标题 + 数量徽标 + 右侧「查看全部」链接）。
- **GitHub 中文加工展示**：卡片主标题保持原 `fullName`（英文仓库名不翻译）；描述行优先展示 `summaryZh`（无则回退 `description`）；`highlightZh` 存在时以 `bg-brand-soft text-primary` 小标签或斜体附加说明形式展示在描述下方一行，语义类似"AI 点评"，不新增图标之外的视觉噪音。

## 四、全量交互状态

- **KPI 概览条**：点击整条跳转 `/applications?view=analytics`；加载中用骨架条占位；接口失败时整条隐藏（不阻塞其余区块渲染，与其他区块一致的降级策略）。
- **待办区块**：与原悬浮面板内容一致——点击行跳 `/applications?id=`；空态"暂无待办安排"；错误态 + 重试；底部/右上角「查看全部」跳 `/applications`。
- **新增岗位区块**：与原悬浮面板内容一致——点击行跳原文链接或 `/jobs`；显示"今天开放/昨天开放"标签；空态含"去招聘聚合看看"引导；底部/右上角「查看全部」跳 `/jobs`。
- **AI 日报 / GitHub Tab、简历项目推荐**：交互不变（Tab 切换、展开详情、容器内固定高度滚动），仅整体下移一层。
- **GitHub 中文加工降级**：`summaryZh`/`highlightZh` 为空时静默回退英文 `description`，不展示"翻译失败"等错误态（后端未配置系统级 AI 或加工失败是预期可能情况，不视为错误）。

## 五、响应式适配规则

| 断点 | 布局 |
|---|---|
| `>=1024px` | KPI 横排 4 卡；待办/新增岗位左右并排；日报Tab、项目推荐纵向堆叠占满宽度 |
| `<1024px` | KPI 横排 4 卡（可换行为 2x2）；待办/新增岗位单列堆叠；其余不变 |

- 移除悬浮球后不再需要为悬浮面板保留 `z-50` 层级与视口宽度计算；页面级横向滚动规则不变（无）。

## 六、无障碍与易用性

沿用 v1-v3 全部要点。新增：KPI 概览条整体 `role="button"` + `aria-label="查看求职数据分析"`；待办/新增岗位区块标题行「查看全部」使用 `<a>` 原生链接语义（非 `button`），保证键盘可达与语义正确；GitHub 中文点评作为补充说明文本，不影响原有链接可达性。
