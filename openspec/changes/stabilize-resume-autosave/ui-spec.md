## 页面目标

在现有简历编辑器工作区中提供低干扰、可确认的自动保存反馈，让用户知道内容已经保存在本地、正在同步云端，或云端同步失败；不新增保存按钮，不改变编辑器主布局。

## 页面结构

- 保存状态放在“简历预览”顶部工具栏的中央槽位，位于左侧标题/快照标签与右侧缩放控制之间。
- 中央槽位使用稳定的最小宽度并居中展示图标与短文本，状态切换不能推动两侧内容或改变预览区域高度。
- 工作区通知仍可在中央区域展示，但保存状态优先可见；通知内容不得挤压或遮挡右侧缩放控制。
- 错误详情继续进入现有工作区通知中心；中央保存状态只显示短状态和重试入口。

## 状态与交互

| 状态 | 展示 | 交互 |
|---|---|---|
| 编辑中 | `编辑中` | 不打断输入 |
| 保存中 | `正在保存...` | 禁止重复触发同一 revision |
| 已保存 | `已自动保存 HH:mm` | 不弹 Toast |
| 本地待同步 | `已保存在本地，等待同步` | 可点击重试 |
| 失败 | `保存失败` | 通知中心显示原因和重试按钮 |
| 离线 | `离线，已保存在本地` | 网络恢复后自动消失 |

## 视觉约束

- 沿用项目现有字体、颜色和间距，不新增独立视觉主题。
- 成功状态使用低对比度中性/绿色提示；失败状态使用现有 warning/error 语义色。
- 不使用模态弹窗、不使用成功 Toast、不显示技术错误堆栈。
- 状态容器应固定最小宽度，避免保存中/已保存切换导致工具栏布局跳动。

## 响应式与无障碍

- 桌面端显示图标与状态文字；预览区域变窄时优先截断普通通知，保留保存状态和缩放控制。
- 状态变化使用 `aria-live="polite"`，错误通知使用现有可访问通知机制。
- 重试按钮必须支持键盘操作并有明确可读名称。

## 验证

- 在桌面和移动宽度下确认状态不遮挡编辑器和预览区。
- 模拟保存中、失败、离线、恢复网络和成功重试，确认状态变化可见且不弹冲突选择框。
