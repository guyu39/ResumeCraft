# 登录与注册页面 UI 规范

## 页面目标与用户场景

- 页面核心任务是完成登录或注册；产品介绍只用于建立信任和说明当前能力，不与表单争夺注意力。
- 登录用户可在密码登录与验证码登录之间切换；新用户可完成邮箱验证码注册。
- 会话过期或被其他设备顶下线时，用户能理解原因并立即重新登录。
- 不提供“忘记密码”，验证码登录即为无密码访问路径。

## 页面结构与顺序

1. 页面根容器：最小高度为动态视口高度，使用柔和蓝灰色实底背景，允许内容超高时原生纵向滚动，不接管滚轮。
2. 内容容器：最大宽度 `1184px`，桌面端双栏，左侧约 `56%`、右侧约 `44%`；整体垂直居中并保留 `32px` 以上边距。
3. 产品区：品牌名称、单句价值说明、三张半透明能力小卡片和简短页脚。能力按“简历制作”“AI 定向适配”“投递管理”排列。
4. 认证区：唯一的有边框工具容器，顺序为标题、辅助文案、会话通知、登录方式标签、表单、登录/注册切换操作。
5. 移动端：品牌名称简写在顶部，认证区紧随其后；完整价值说明与三条能力列表排在认证区后，保持页面第一屏优先出现表单。

## 视觉规范

- 颜色：页面背景使用柔和蓝灰色 `#e8eef2`，认证区使用半透明白色，主文字 `slate-900`，次文字 `slate-600`；主操作使用现有 `primary`，深色提交按钮使用 `slate-900`。
- 禁止渐变、渐变文字、光斑和漂浮装饰；半透明只用于认证容器、输入框和三张能力卡，保持边界清晰，不堆叠多层装饰性玻璃卡片。
- 字体沿用项目应用 UI 默认字体；页面标题 `24px/700`，品牌名桌面 `36px/700`、移动 `22px/700`，正文 `14-16px`；字距固定为 `0`。
- 认证容器最大宽度 `440px`，圆角 `8px`，使用约 70% 白色背景和轻量背景模糊，阴影不超过 `0 16px 40px rgba(15,23,42,0.08)`。
- 控件高度至少 `44px`，圆角 `6-8px`；图标按钮固定为 `40px` 宽高，避免切换状态引发布局移动。
- 能力卡使用 36px 图标底座、半透明白色背景、1px 浅色边界和 `8px` 圆角；三张卡片间距 `12px`，不得嵌套进另一张卡片。

## 表单与交互状态

- 标签：每个输入上方显示持久标签；必填字段不依赖占位符表达含义。
- 默认：输入框使用半透明白色背景和 `slate-300/80` 边框；悬停增加背景不透明度并将边框变为 `slate-400`；焦点使用 `primary` 边框和浅色焦点环。
- 错误：输入边框变为 `red-400`；错误文案在字段标题行右侧显示为浅红背景、浅红边界的紧凑消息气泡，并用小尾角指向输入区域。错误元素使用稳定 ID，并由输入的 `aria-describedby` 引用。
- 提交校验：当前模式所有必填字段同时显示错误，焦点移动到首个无效字段；不得只显示 Toast。
- 密码按钮：位于输入右侧，使用 Lucide `Eye`/`EyeOff`；按钮带 `title` 和动态 `aria-label`，焦点样式清晰。
- 登录方式：使用两段式标签控件，当前项白底、深色文字和轻阴影，非当前项中性文字；支持键盘焦点和 `aria-selected`。
- 验证码按钮：与输入同排，固定最小宽度；发送中、倒计时和禁用态不改变容器宽度。
- 加载：提交按钮保持尺寸，登录显示“登录中...”，注册显示“注册中...”，并禁用重复提交。
- 会话通知：使用现有琥珀色提醒，保持 `role="alert"`。
- 操作结果：验证码发送成功和接口错误继续使用 Toast；客户端字段错误不额外弹重复 Toast。
- 能力卡悬停：卡片最多向上移动 `4px`，背景稍微变亮并增强阴影，图标可轻微缩放；动画时长 `200ms` 左右，不改变布局尺寸。

## 响应式规则

- `>= 1024px`：双栏单屏布局，表单始终完整可见；注册态使用 20px 卡片内边距、12px 字段间距和紧凑底部切换间距，桌面页面上下安全边距缩至 8px，不创建第二屏、内部滚动或页面滚动条。
- `768-1023px`：单列居中，认证区优先，产品能力在下方；内容最大宽度 `640px`。
- `< 768px`：页面水平内边距 `16px`；认证区内边距 `20-24px`；验证码输入与按钮同排，最窄 320px 不溢出。
- 错误气泡始终位于字段标题行内部并右对齐，最长错误可换行，不得越出认证容器或遮挡字段标签。
- `< 1024px` 时注册表单超出视口可使用文档原生滚动，顶部和底部保留安全间距；桌面端 1280x720 及 1024x640 必须完整容纳注册卡，不得出现文档级纵向滚动条。
- 375x812、768x1024、1280x800 下不得出现控件重叠、文字截断或不可见操作。

## 无障碍与易用性

- 所有输入必须包含 `id`、`name`、正确的 `autoComplete` 和关联 `label`。
- 可见错误时设置 `aria-invalid="true"` 与 `aria-describedby`；隐藏错误不占用辅助技术描述。
- 密码按钮和标签按钮必须进入正常 Tab 顺序；页面中不存在透明但仍可聚焦的内容。
- 装饰性图标使用 `aria-hidden="true"`；只有图标的按钮必须提供可访问名称和 tooltip。
- 保持原生表单提交、按钮 disabled 和浏览器自动填充能力。
- `prefers-reduced-motion` 下能力卡取消位移和图标缩放，只保留背景、阴影和焦点颜色变化。

## 验收清单

- 空表单提交时，各必填字段标题右侧出现错误消息气泡，焦点位于第一个错误输入。
- 浏览器 DOM 中可验证字段语义、错误关联和登录标签状态。
- 密码与确认密码可独立显示/隐藏，输入值不丢失。
- 桌面没有双相位或滚轮拦截，移动端表单先于完整能力列表。
- 页面准确展示三个产品闭环，不出现忘记密码入口。
- 登录、验证码登录、注册、会话失效和顶号确认现有流程无回归。
- 页面有清晰背景色，输入框与三张能力卡呈现半透明效果；能力卡悬停时有轻量动画且不会引发布局移动。
